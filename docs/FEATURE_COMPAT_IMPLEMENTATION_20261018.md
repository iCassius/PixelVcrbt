# 按特征判断是否启用：本轮实现

2026-10-18。基于 `main@d153004` 的本地修改，未提交或发布。后续已按用户授权沿用原签名安装、重新加载电话进程并拨打指定联系人；首个候选失败后修正，复测通过，见 [实机记录](DEVICE_TEST_20261018.md)。未修改独立 PixelIMS 模块或通信配置。

## 行为变化

- 删除业务 Hook、状态页和配置兜底中的电话版本、机型、系统构建号限制。版本号仅出现在诊断记录与模块自身更新比较中，不决定电话是否可用。
- `DialerFeatures` 检查具备明确业务含义的入口类、继承关系，以及 `onCallAdded(Call)void`、`onCallRemoved(Call)void`。`FeatureContract` 只接受完整参数、返回类型和具体实例方法；继承方法可用，同名无关重载不会被安装。当前只有一套入口契约，后续若电话入口结构改变，应增加有明确依据的特征契约，不猜混淆类或扩大作用域。
- 必要步骤先解析再安装。主线程只尝试一次；未全部完成前，回调直接执行原生逻辑。失败按逆序撤回 Hook 并注销生命周期回调；即使某项撤回抛异常，回调也因未进入 ready 而不执行模块逻辑。运行回调抛异常时，停止模块接管并显示“运行异常”；不再次调用已经可能执行过的原生方法。该异常可能来自原生调用，不能只由此归因模块。
- 音频选择保护单独探测三项完整签名。缺失或安装失败时不自动恢复路由；保留用户原生选择。具体 VideoCall 对象出现后再检查 Surface setter 与单参数 `sendSessionModifyRequest(VideoProfile)`；两项都安装成功后才允许模块提交 Surface。首个候选曾错误使用底层 Binder 的双参数形式，现已修正并增加真实 SDK 签名测试。失败不会因先记入缓存而在下一次巡检绕过检查。
- 原生远端视图必须位于 `videocall_video_remote` 语义节点内，满足可见、附着、尺寸和 Surface 就绪要求，且候选唯一。只凭“大尺寸 TextureView/SurfaceView”不再决定接管对象。出现未知或歧义的大尺寸原生视频视图时停止接管；自有兜底视图已存在时，也会重新检查并退出。原生视频、主动视频意图、紧急呼叫排除与会话释放规则保留。
- 配置兜底另查实际 UID 权限、系统 Shannon MMTEL 服务的权限/元数据、CarrierConfig Binder 的完整方法签名、唯一目标订阅、SIM/空闲状态、四项值的类型及有效配置回读。非预期类型不写，无法记录一次尝试时不写。仍只处理既有四项，不改 VoNR/CDMA；持久化方式未改变。识别系统服务并不证明它当前已绑定，回读值也不证明彩铃业务成功。

## 运行确认与页面

回复协议使用 schema 2，保留显式包名、双向电话权限限制和实时 nonce；增加电话进程随机实例、递增序号，以及随源码编译进运行代码的模块版本和源码标识。该标识覆盖 `src/main` 与 `build.py`，不是 APK 文件摘要；同版本的不同代码也能被区分。页面拒绝过期、重复、乱序、前一轮 nonce 或不同进程实例混入的回复，离开页面立即清空实时结果。

入口立即回复，IMS 查询独立合并，最多保留 16 个等待请求，5 秒结束；迟到回调不能结束新的查询，也不能把超时结果改成已注册。IMS 展示不再依赖彩铃 Hook 成功。

主页面仅保留功能开关、四项依赖和三行能力信息：电话入口特征、模块连接、IMS 注册。无回复时不推断功能关闭；“必要项齐备”只指电话入口结构；“已加载”只指必要 Hook 已提交且未报告运行回调异常。不同运行代码或旧协议提示重新加载，页面不会自动重启电话。按需详情显示运行代码标识、适配器、安装步骤、失败位置、音频/兜底状态和最近业务事件，不新增常驻画面/媒体行，不申请 Root。

本轮保持现有权限通道，未实现研究稿中的广播发送者 UID 认证扩展；nonce 和进程标识用于时效及关联，不能作为密码学身份认证。也未加入诊断导出、远程规则或代码下载。
